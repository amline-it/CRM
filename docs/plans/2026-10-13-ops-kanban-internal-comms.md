## ۱) واقعیت موجود مخزن (بازبینی‌شده در همین شاخه)

| موضوع | وضعیت واقعی در کد |
| --- | --- |
| استک | Next.js 16 (App Router، RSC + Server Actions)، TypeScript، SQLite داخلی Node (`node:sqlite`)، Kotlin/FastAPI دیده نمی‌شود |
| احراز هویت | `src/auth` — نشست کوکی/هدر JWT + ردیف `sessions`، scrypt، RBAC دوردیفی (`staff`/`admin`)، CSRF امضاشده |
| واحد سازمانی | `org_units` (مهاجرت ۰۰۰۲) + `staff.org_unit` + `staff.title` |
| کانبان | `cases.kanban_status ∈ (new, in_review, waiting_info, returned_correction, done)` + `referrals` + `/panel/kanban` |
| پرونده | `cases` با سرویس/گردش‌کار/اولویت/سررسید/مسئول؛ `timeline_events` با `visibility` |
| اعلان | `notifications` به‌عنوان صندوق خروجی (channel/template/status) — برچسب `inapp` از قبل در UI هست |
| پیام داخلی | **وجود ندارد** — نه جدول پیام، نه منشن، نه خوانده/نخوانده |
| API پنل | فقط API سینک (`/api/v1/ingest|jobs`) و سلامت؛ تغییرات پنل با Server Action انجام می‌شود |
| تست/CI | Vitest (`npm test`)، `npm run lint` = `tsc --noEmit`، `npm run build`؛ فایل CI در مخزن نیست |

نتیجه: مدل «پرونده = عملیات، واحد = ستون کانبان، وضعیت = فیلد مستقل» از قبل وجود دارد؛ روی همان توسعه می‌دهیم و جدول/API موازی نمی‌سازیم.

## ۲) تغییرات (چک‌لیست اجرا)

- [ ] **مهاجرت ۰۰۰۳**: افزودن وضعیت `cancelled` (لغوشده) به کانبان، غنی‌سازی `referrals`، جدول‌های گفت‌وگو/منشن/خوانده‌شده، ستون‌های صندوق اعلان داخلی + ایندکس‌ها. بازنویسی `cases` نیازمند خاموش‌کردن موقت FK است → پشتیبانی «مهاجرت بدون تراکنش بیرونی با FK خاموش» در `src/db/migrate.ts` و `scripts/migrate.mjs` + اعتبارسنجی `PRAGMA foreign_key_check` قبل از commit.
- [ ] **مخازن**: `src/db/repos/conversations.ts` (پیام/منشن/خوانده‌شده)، توسعه `referrals.ts` (فیلدهای کامل ارجاع)، توسعه `platform.ts` (صندوق اعلان داخلی: خوانده/نخوانده، شمارنده، dedupe).
- [ ] **سرویس‌ها**: توسعه `referral-service.ts` (ارجاع کامل + اقدام + لغو + تخته با فیلتر و شمارنده پیام)، سرویس جدید `conversation-service.ts` (پیام/منشن/ویرایش/حذف نرم)، `ops-notify.ts` (اعلان داخلی + sweep سررسید با dedupe).
- [ ] **API نسخه‌دار کارمندی** زیر `/api/v1/ops/*` با نشست + CSRF + RBAC + Idempotency-Key: `board`, `cases/[id]/refer`, `cases/[id]/actions`, `cases/[id]/messages`, `messages/[id]`, `notifications`, `notifications/count`, `staff`, `jobs/ops-reminders`.
- [ ] **UI**: تب «کانبان عملیات» با فیلترها/جست‌وجو/شمارنده پیام/کارت بدون مسئول/عقب‌افتاده، مودال کارت با گفت‌وگو + مسیر ارجاع + باکس اقدام سریع، باکس «اقدام سریع» و پنل گفت‌وگو در صفحه پرونده (ویزارد خدمات)، صفحه «صندوق اعلان» با شمارنده در ناوبری.
- [ ] **seed**: واحدهای فروش/مدیریت/فنی + داده نمونه گفت‌وگو، منشن و اعلان (بدون حذف داده قبلی).
- [ ] **تست‌ها**: ۱۴ سناریوی پذیرش + مهاجرت روی داده موجود + idempotency + مجوزها؛ اجرای `npm test`, `npm run lint`, `npm run build`.
- [ ] **پیش‌نمایش زنده** با `LOCAL_DEMO_MODE=true` روی دیتابیس نمونه.

## ۴) قواعد امنیتی (سرور‌محور)

* مشاهده پرونده‌ها و پنل کاربران مثل قبل برای کارشناس/مدیر باز است (کاهش دسترسی نداریم).
* ارجاع/اقدام/پیام: نیازمند `referral.create` + «مسئول بودن در واحد جاری یا مدیر».
* منشن فقط به کارمندی که مجوز مشاهده پرونده دارد اعلان می‌دهد و مسئولیت منتقل نمی‌کند.
* پیام‌های داخلی در جدول جدا (`case_messages`) هستند و هرگز در API سینک، وب‌هوک خروجی و اعلان مشتری ظاهر نمی‌شوند.
* هیچ نقش «God Mode» یا دسترسی سراسری جدیدی ساخته نمی‌شود.
